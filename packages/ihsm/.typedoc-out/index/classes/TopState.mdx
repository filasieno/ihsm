Abstract root class for every state in the hierarchy.

States are **never constructed directly** — the runtime binds one instance object whose
prototype moves along the class chain. Subclass `TopState` (or a child state), implement
your `Protocol` methods, and pass the root class to [makeHsm](../functions/makeHsm.mdx).

Forwards [State](../interfaces/State.mdx) / [Properties](../interfaces/Properties.mdx) APIs and default [StateEvents](../interfaces/StateEvents.mdx) behavior.

## Methods

### transition()

> **transition**(`nextState`): `void`

Schedule an **external** transition to `nextState` after the current handler completes.

Does **not** run exit/entry immediately. When the handler returns successfully (including
after awaiting an `async` handler's Promise), the runtime:

1. Computes the **lowest common ancestor (LCA)** on the class prototype chain
2. Runs `onExit()` from the current leaf up to (but not including) the LCA
3. Switches the instance prototype to `nextState` (descending `@InitialState` chains for composites)
4. Runs `onEntry()` down from the LCA to the target leaf

#### Parameters

##### nextState

[`StateClass`](../type-aliases/StateClass.mdx)\<`Context`, [`Dispatch`](../type-aliases/Dispatch.mdx)\<`Protocol`, `InternalProtocol`\>\>

Destination state **class** constructor (not an instance)

#### Returns

`void`

#### Remarks

- **Self-transition** to the same leaf with unchanged initial descent: optimized to skip exit/entry
- **Internal transition:** omit `transition()` — active class unchanged, no exit/entry
- **`transition()` inside `onEntry`/`onExit`:** scheduled transition is **cleared** when that lifecycle dispatch ends — use [post](../interfaces/State.mdx#post) from `onEntry` for follow-up work
- Transition paths are **cached** per `From=>To` pair for hot loops
- Only the **last** `transition()` call wins if invoked multiple times in one handler

#### Implementation of

[`State`](../interfaces/State.mdx).[`transition`](../interfaces/State.mdx#transition)

> **unhandled**(): `never`

### sleep()

> **sleep**(`millis`): `Promise`\<`void`\>

Pause the **current handler** without blocking the JavaScript event loop.

Returns a Promise resolved after `millis` milliseconds via `setTimeout`. The actor
remains **locked** to this handler until the Promise settles (run-to-completion) — other
`post`/`call` jobs queue but do not run.

#### Parameters

##### millis

`number`

Sleep duration in milliseconds (≥ 0)

#### Returns

`Promise`\<`void`\>

Promise that resolves (never rejects) when the delay elapses

#### Remarks

Use for simple delays inside handlers. For calendar-time deferral of **new** events,
prefer [deferredPost](../interfaces/State.mdx#deferredpost). Composable with `async` handlers: `await this.sleep(100)`.

### post()

> **post**\<`EventName`\>(`eventName`, ...`eventPayload`): `void`

Enqueue a **normal-priority** event for later dispatch on the active state.

Returns immediately; the handler runs asynchronously when the actor reaches this job.
Dispatch walks the **prototype chain** from the current leaf upward until a method named
`eventName` is found.

#### Type Parameters

##### EventName

`EventName` *extends* `string` \| `number` \| `symbol`

Literal key of `Protocol` being posted

#### Parameters

##### eventName

[`PostedEvent`](../type-aliases/PostedEvent.mdx)\<[`Dispatch`](../type-aliases/Dispatch.mdx)\<`Protocol`, `InternalProtocol`\>, `EventName`\>

Event or service name. Must be `keyof Protocol` and must **not** collide
  with reserved [State](../interfaces/State.mdx) method names (`transition`, `post`, `ctx`, …)

##### eventPayload

...[`EventPayload`](../type-aliases/EventPayload.mdx)\<[`Dispatch`](../type-aliases/Dispatch.mdx)\<`Protocol`, `InternalProtocol`\>, `EventName`\>

Arguments tuple inferred from `Protocol[eventName]` handler parameters.
  For **events**, pass every parameter **except** `resolve` / `reject`. For fire-and-forget
  events, the handler return type must be `void` or `Promise<void>`

#### Returns

`void`

#### Remarks

**Client usage:** `door.post('open')` then `await door.sync()` to wait for completion.

**Handler usage:** `this.post('tick')` schedules work **after** the current handler returns
and after any [State.transition](../interfaces/State.mdx#transition) it requested. Normal-priority posts run **after** all
[State.postNow](../interfaces/State.mdx#postnow) hi-priority jobs drained for the current turn.

**Ordering:** FIFO among normal-priority jobs. Multiple posts before one `sync()` are
processed in submission order.

**Typing:** With `Protocol extends undefined`, accepts any `string` and `any[]` (legacy mode).

#### Implementation of

[`State`](../interfaces/State.mdx).[`post`](../interfaces/State.mdx#post)

### deferredPost()

> **deferredPost**\<`EventName`\>(`millis`, `eventName`, ...`eventPayload`): `void`

Schedule a normal-priority [post](../interfaces/State.mdx#post) after a wall-clock delay. **Handler-only.**

Backed by the machine's [Port](Port.mdx) timer service: when no custom port is supplied the
runtime instantiates a [Port](Port.mdx) whose `setTimeout`-based timer is used here. When
the timer fires, the event is enqueued like an ordinary `post`. This is intentionally **not**
on the external [Hsm](../interfaces/Hsm.mdx) / [Actor](../type-aliases/Actor.mdx) surface — clients schedule work via [post](../interfaces/State.mdx#post).

#### Type Parameters

##### EventName

`EventName` *extends* `string` \| `number` \| `symbol`

Literal key of `Protocol` being scheduled

#### Parameters

##### millis

`number`

Delay in milliseconds before enqueueing (≥ 0). Subject to timer granularity

##### eventName

[`PostedEvent`](../type-aliases/PostedEvent.mdx)\<[`Dispatch`](../type-aliases/Dispatch.mdx)\<`Protocol`, `InternalProtocol`\>, `EventName`\>

Event name (same constraints as [post](../interfaces/State.mdx#post))

##### eventPayload

...[`EventPayload`](../type-aliases/EventPayload.mdx)\<[`Dispatch`](../type-aliases/Dispatch.mdx)\<`Protocol`, `InternalProtocol`\>, `EventName`\>

Handler arguments tuple (same as [post](../interfaces/State.mdx#post))

#### Returns

`void`

#### Remarks

Does **not** block the calling handler — returns as soon as the timer is registered. Timers
are **not** cancelled if the machine transitions or the scheduling handler throws. (Richer
timer services — cancellation, virtual clocks — will arrive later through the port.)

### postNow()

> **postNow**\<`EventName`\>(`eventName`, ...`eventPayload`): `void`

Only valid **inside** a running handler (`this.postNow`). Clients must use [post](../interfaces/State.mdx#post).
Hi-priority jobs drain immediately after the current handler and its transition complete,
**before** any normal-priority posts the handler enqueued (including chained `this.post`).

#### Type Parameters

##### EventName

#### Parameters
